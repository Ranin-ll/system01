V1 → V2 修订摘要（8 处优化）

V1 只有 6 节：信息架构 + 看板 + 两级下钻 + 账号管理 + 权限对照。V2 把它补成一份可施工的完整稿。

#修订点V1 的问题V2 的做法
1目录从 3 项扩到 5 项「三项目录」把系统管理挤到业务目录里，与原生菜单打架全局工作台 / 组织与人员 / 培养运营 / 规则与配置 / 系统管理（原生 18 项直接复用）
2补齐「规则与配置」超管唯一能改的考核侧内容（门槛 / 权重 / 补考 / 协议模板 / 证书模板）无落点新增第 4 目录，逐项给出字段与影响范围
3只读边界可视化只在文字里提了一句「只读」每页顶部标「只读 / 可写 / 可代操作」，并给后端已有校验点（6 个 Service）
4看板拆成 6 个指标 + 3 张对比图指标混在一个卡里，且不区分真实/示例KPI 逐项标注数据来源与口径，示例值统一打 示例

②

为什么不是「部门端 × 5 倍」

职责不同，不是放大版。部门管理员是生产者（写课程、发考核、批阅、终审转正）； 超管是裁判与运维（看全局数据、定规则、管账号与系统）。因此超管的业务侧页面全部只读， 且不出现「代部门发布 / 代批阅」的按钮 —— 避免两个角色在同一份数据上互相覆盖。
✓能看：全部门课程 / 题库 / 考核 / 成绩 / 画像
✓能改：考核规则、协议与证书模板、账号与角色
✕不能：改课程内容、发考核、批阅答卷、审批转正
✕不能：修改任何业务实例的历史数据
后端已在 Course / CourseContent / Exam / Question / QuestionBank / PracticeSubject 六个 Service 里实现 isGlobalReadOnly()，命中即抛「超级管理员仅可查看…，不能执行写入操作」。
